Dual-Stage Guardrail Architecture

          Specification & Design
        


        

          Nyaya-Guard implements a fail-fast, fail-closed dual-stage pipeline protecting legal AI workflows against data leakage, instruction hijacking, hallucinations, and format deviations.
        


        

          
          

            
Stage 1: Input Guardrails

            
            

              
1. Input Normalizer & Validator

              
Approach: Unicode NFKC normalization, zero-width stripping (\u200b, \ufeff), Cyrillic homoglyph lookalike substitution, control char filtering.

              
Action: Rejects null bytes and structural malformations. Passes normalized text.

              
Limitation: Extreme multi-script combinatorial encodings may require expanded dictionaries.

            


            

              
2. Prompt Injection Detector

              
Approach: 35+ compiled regex patterns (Overrides, DAN mode, Prompt Extraction, Impersonation, Context Delimiters) + Shannon entropy and system command heuristic flags.

              
Action: Immediate hard block with threat category and composite risk score.

              
Limitation: Indirect semantic paraphrasing and novel low-resource linguistic jailbreaks.

            


            

              
3. PII Detection & Anonymization Engine

              
Approach: Deterministic regex bank for Emails, Phone Numbers (+977 / international), Nepal Citizenship Numbers, PANs, SSNs, Passports, and adversarial spacing/at-dot obfuscation.

              
Action: Sanitizes input via Redaction, Masking, or Tokenization before model ingestion.

              
Limitation: Unstructured full human names without legal context keywords.

            


            

              
4. Sensitive Topic Classifier & Crisis Router

              
Approach: Multi-class keyword and regex matching across Weapons/CBRN, Cyberweapons, Extremism, CSAE, Financial Fraud, and Self-Harm/Crisis.

              
Action: Prohibited topics trigger hard_block; Self-harm queries trigger safe_response providing certified crisis hotlines (Nepal 1166 Helpline / Police 100).

              
Limitation: Polysemous terms in academic historical discussions.

            

          


          
          

            
Stage 2: Output Guardrails

            
            

              
1. Output Schema Validator

              
Approach: JSON extraction from markdown code fences, balanced brace detection, syntax repair, and validation against LegalAIResponseStructure.

              
Action: On failure, generates structured corrective retry prompt detailing missing fields and invalid types.

              
Limitation: Deeply nested arbitrary schema graphs with dynamic conditionals.

            


            

              
2. Sensitive Information & Secret Detector

              
Approach: Re-scans generated output for unredacted user PII, API tokens, cryptographic keys, and integrity canary tokens.

              
Action: Redacts confidential strings, or executes immediate refusal if canary leaks.

              
Limitation: Stolen internal secrets disguised as generic English words.

            


            

              
3. Groundedness & Hallucination Checker

              
Approach: Extracts atomic propositional claims from narrative fields, tests lexical token overlap and statutory citation integrity against source reference context; detects hedging phrases.

              
Action: If score < domain threshold (0.85 for Legal), intercepts output and returns certified Safe Fallback response.

              
Limitation: Pure deductive reasoning where conclusions use distinct vocabulary from premises.
